# ДЗ-1: автотесты REST API Restful Booker (TypeScript)

Автотесты для публичного API бронирований **Restful Booker**: https://restful-booker.herokuapp.com
Документация API: https://restful-booker.herokuapp.com/apidoc/index.html
Задание: [docs/HW-1.md](docs/HW-1.md). Тест-кейсы: [docs/TEST_CASES.md](docs/TEST_CASES.md).

### Стек
| Инструмент | Зачем |
|---|---|
| **TypeScript** (Node.js ≥ 20) | язык тестов; типы ловят опечатки в полях брони ещё до запуска |
| **Playwright Test** | запуск тестов, HTTP-клиент, фикстуры (подготовка и очистка данных), HTML-отчёт |
| **Ajv** | проверка ответов по JSON Schema |
| **@faker-js/faker** | тестовые данные |

### Тестируемые эндпоинты
| Метод | Путь | Тесты |
|---|---|---|
| GET | `/ping` | HC-1 |
| POST | `/auth` | AU-1, AU-2 |
| POST | `/booking` | CR-1 … CR-7 |
| GET | `/booking`, `/booking/{id}` | GT-1 … GT-4 |
| PUT, PATCH | `/booking/{id}` | UP-1 … UP-3 |
| DELETE | `/booking/{id}` | DL-1 … DL-3 |

### Сценарии
- **Позитивные:** ping; получение токена; создание брони, в том числе без необязательного поля; чтение по ID с проверкой JSON Schema; фильтр по имени; PUT с токеном, PATCH с Basic auth; DELETE.
- **Негативные:** неверный пароль; бронь без обязательного поля; невалидный JSON; нечисловой ID → 404; `Accept: text/plain` → 418; PUT и DELETE без прав → 403, данные не меняются.
- **Граничные:** `totalprice = 0`; однодневная бронь (`checkin == checkout`); строка в 300 символов, кириллица, спецсимволы и emoji.

Изменяющие операции дополнительно проверяются повторным GET. Ответы сравниваются с отправленными данными, а структура ответа — с JSON Schema из папки `schemas/`. У текстовых ответов (ошибки, `201 Created`) проверяются статус, `Content-Type` и тело.

### Структура проекта
```
playwright.config.ts   проекты запуска: stand, api, known-bugs
schemas/               JSON Schema ответов
src/
  config/    параметры запуска (переменные окружения)
  models/    типы: Booking, Auth и т. д.
  http/      обёртка над HTTP-клиентом Playwright: заголовки, лог запросов с маскировкой пароля и токена
  clients/   AuthClient, BookingClient, HealthClient — только запросы, без проверок
  data/      BookingBuilder — генерация валидной брони с уникальными именами
  support/   проверки ответов, JSON Schema, удаление созданных броней, общие шаги тестов
  fixtures.ts  фикстуры Playwright
tests/
  setup/     ожидание стенда перед прогоном
  api/       тесты
```

- **Изоляция данных.** Каждый тест создаёт свои брони с уникальными именами, а после теста они удаляются (фикстура `bookings`), даже если тест упал.
- **Проверка стенда.** Перед тестами `GET /ping` опрашивается, пока стенд не ответит (Heroku после простоя долго «просыпается»). Если стенд недоступен, тесты не запускаются.
- **Лог при падении.** У упавшего теста в консоль и в HTML-отчёт выводятся все его запросы и ответы; пароль и токен заменяются на `***`.
- **Воспроизводимые данные.** Данные генерируются от seed; при падении печатается строка `BOOKER_SEED=… BOOKER_RUN_ID=… BOOKER_BASE_DATE=…`, с которой можно повторить те же данные.

### Запуск
Нужны Node.js 20+ и доступ в интернет.

```bash
npm install                     # установить зависимости
npm test                        # основной набор
npx playwright test -g "CR-1"   # один тест по части названия
npm run test:known-bugs         # тесты известных дефектов
npm run typecheck               # проверка типов
npm run report                  # HTML-отчёт
```

Параметры (переменные окружения): `BOOKER_BASE_URL` (по умолчанию `https://restful-booker.herokuapp.com`), `BOOKER_TIMEOUT` (30000 мс), `BOOKER_STAND_WAIT` (60000 мс), `BOOKER_USERNAME` / `BOOKER_PASSWORD` (`admin` / `password123` — публичные демо-креды из документации API), `BOOKER_SEED`, `BOOKER_RUN_ID`, `BOOKER_BASE_DATE`.

### Как тестируются известные дефекты
У каждого дефекта два теста:
- **в основном наборе** — фиксирует текущее ошибочное поведение; в названии пометка `[known bug: текущее поведение]`. Если API исправят, тест упадёт и подскажет, что ожидание пора менять;
- **с тегом `@known-bug`** — проверяет правильное поведение и сейчас падает. Из основного прогона исключён, запускается `npm run test:known-bugs`. PASSED здесь означает, что дефект исправлен.

### Особенности API (тестируются как есть)
- Неверные креды в `/auth` возвращают **200** и `{"reason":"Bad credentials"}`, а не 401.
- Изменение без авторизации или с невалидным токеном возвращает **403**, а не 401.
- `Accept: text/plain` даёт **418 I'm a Teapot**. Несколько типов в `Accept` тоже дают 418, поэтому клиент отправляет ровно `Accept: application/json`.
- Ошибки и `201 Created` приходят как `text/plain`, а не JSON.

### Что не тестировалось
- Время ответа и нагрузка — это чужой публичный стенд.
- Ограничение длины строк не документировано; CR-4 фиксирует фактическое поведение (300 символов принимаются).
